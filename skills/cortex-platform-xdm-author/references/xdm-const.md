# XDM_CONST constants -- closed lists

XDM fields with type `XDM_CONST` must be assigned using the appropriate constant. Never quote them. Write `XDM_CONST.OUTCOME_SUCCESS` not `"XDM_CONST.OUTCOME_SUCCESS"`.

Every constant group below is a CLOSED LIST. Do NOT invent constants that are not shown. If a vendor value does not match any listed constant, either OMIT the `XDM_CONST` field entirely or fall back to the String alternative documented in [pitfall-traps.md](pitfall-traps.md). Never guess by appending a plausible-sounding suffix (e.g. `THREAT_CATEGORY_SECURITY`, `CLOUD_PROVIDER_ORACLE`, `OS_FAMILY_BSD`) -- speculative constants cause hard validation errors in the Cortex IDE.

member enumerated here is the authentication-story tag, which is

`arraycreate()` because `xdm.event.tags` is an array.

## Other XDM_CONST groups (NOT enumerated here)

The following groups have large, vendor-specific, or unstable value lists and are NOT enumerated in this file. For these, follow the OMIT-and-fall-back rule in [pitfall-traps.md](pitfall-traps.md) -- do NOT invent constants.

`AGENT_TYPE`, `CLOUD_SERVICE_TYPE`, `DCERPC_OPERATION`, `DHCP_MESSAGE_TYPE`, `DNS_RECORD_TYPE`, `DNS_RESPONSE_CODE`, `DB_OPERATION`, `EVENT_TAG`, `INTEGRITY_LEVEL`, `LDAP_BIND_AUTH_TYPE`, `LDAP_OPERATION`, `LDAP_SCOPE`, `REGISTRY_VALUE_TYPE`, `SCOPE_TYPE`, `SIGNATURE_STATUS`, `URL_CATEGORY`.

If a vendor value definitively maps to a member of one of these groups and the user can confirm, you may use it -- otherwise leave the XDM target unset or use the String fallback documented in [pitfall-traps.md](pitfall-traps.md).
